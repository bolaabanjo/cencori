Basecode runs commands and edits files on your machine, so it runs inside a sandbox. The mode you pick sets the boundary of that sandbox for the task.

You change the mode from the composer, and it applies to the tasks you start after changing it.

## Plan

**Read-only.** Basecode can read files and run commands that inspect the project, but it cannot write to your workspace.

Use it to understand unfamiliar code, scope a change before committing to it, or get a plan you intend to review before any of it is carried out.

## Manual and Auto

**Workspace-write.** Basecode can read and edit files inside the workspace you opened, and run commands there. Anything beyond that boundary — writing outside the workspace, or an action the sandbox refuses — surfaces as an approval request you answer in the app.

Network access is on. An agent that cannot reach your dev server or your package registry cannot run your tests or confirm that a change works, and a change it could not verify is worth much less than one it could.

Manual and Auto currently apply the same workspace-write boundary and the same approval behaviour. They are separated in the interface so the distinction can tighten later without moving anyone's default.

## Bypass permissions

**Full access, no sandbox.** Basecode can read and write anywhere your user account can, and commands run without sandbox restrictions or approval prompts.

Use it deliberately and briefly — a migration that has to touch files outside the workspace, or tooling that will not run under a sandbox. It removes the boundary that keeps a mistaken command inside the project folder, so it is the wrong default for everyday work.

## Approvals

In every mode except Bypass permissions, an action outside the current boundary pauses the task and asks you. You approve or decline in the app, and the task continues either way — declining is a normal answer, not an error.

Basecode captures the previous contents of any file before it edits it, in every mode, so [Undo](/docs/basecode) stays available regardless of the boundary you chose.
